# 中国古典诗词

**中国古典诗词检索、阅读与探索**

中国古典诗词目前收录七个文库、三十二万余首作品。

## 产品结构

- **首页与搜索**：统一的搜索入口与结果页，按关键词匹配题目、作者、词牌与正文；另索引《诗经》篇章信息，不支持意象、主题分类或风格的语义检索
- **高级搜索**：选择文库后，筛选按作者、句式、句数、检索排列；作者支持下拉搜索和滚动多选，句数按文库实际数据单选；展示当前筛选结果的作品、作者、正文汉字与句数总数
- **阅读**：拥有稳定 URL、结构信息与相邻作品导航的专注阅读页
- **统计分析**：与高级搜索共用筛选条件，展示匹配作品的作者、句数、句式与正文语言频率分布

搜索使用 `/?q=关键词`，文库范围与页码分别保存在 `corpus`、`page` 参数中，
支持分享链接与浏览器前进、后退。旧 `/search` 链接保留参数并重定向至首页。
切换顶栏页面时保留当前内容，点击的导航项即时高亮并显示加载指示，目标页面准备好后直接切换，
不显示整页加载占位框；减少动态效果设置下，加载指示保持静态。

高级搜索位于 `/corpora`，默认文库为唐诗三百首（`ts300`），关键词可留空。`corpus` 为单个文库，重复的 `author`
参数用于多选作者，`lineType` 用于格式筛选（按每句字数），`sentenceCount` 用于精确匹配每首作品的句数。
句数下拉框仅提供当前文库实际存在的句数，默认“不限”；旧链接中的 `minSentences`、`maxSentences` 不再参与筛选。
所有选择即时生效；关键词输入停顿 400 毫秒后自动更新，中文输入法组词期间不触发搜索。
更新不打断输入或关闭作者下拉框，修改条件时返回第一页。
同一作者条件内取并集，不同筛选条件之间取交集；切换文库会保留关键词并清除其他筛选，
分页与分享链接保留当前条件。字数和句数来自原始结构数据，不推断绝句、律诗等诗体。
作者下拉框的作品数随检索、句式和句数条件更新，不受已选作者或分页影响；简繁体等归一为同一作者的选项显示相同计数。
作者选项保留文库原有顺序，零匹配显示 0；条件更新中或无效时显示 `--`，避免展示过期数字。

统计分析位于 `/insights`，使用与高级搜索相同的参数，默认文库同为 `ts300`。
通过顶栏或筛选区链接在两页间切换时，保留当前全部条件（包括尚在等待自动更新的输入），返回作品列表时从第一页开始。
图表与结果列表使用同一筛选逻辑，统计所有匹配作品，不受分页限制；两页筛选区的四个总数均随当前条件一起更新。
无附加条件时复用预计算统计；有条件时遍历匹配作品，按数据构建时相同的标点边界与候选词机制统计语言频率。
旧 `/insights/文库标识` 链接保留筛选条件并重定向至新地址。

手机端检索独占一行；窄屏作者独占一行，句式和句数并排，放大文字后可自动改为单列。
输入字号避免触发 iPhone 自动放大，主要触控操作至少高 44px。
作者下拉框随可视区域、页面滚动和软键盘调整位置与高度；手机端顶栏随页面滚动，给正文和软键盘留出空间。
搜索输入提供相应的软键盘操作键，提交搜索或完成作者输入后收起键盘；自动筛选时仍保留输入焦点。
宽表格在卡片内横向滚动，图表横轴按可用宽度减少标签；长标题与放大文字可换行，页面不限制用户缩放。

## 架构

应用是一个 Next.js 服务，部署时由 Docker 构建：

1. 读取本仓库固定的 `data_release.json`。
2. 从独立的
   [`vippeterhou/shici-data`](https://github.com/vippeterhou/shici-data)
   GitHub Release 下载压缩 JSONL。
3. 验证每个资源的 SHA-256 与作品数量。
4. 生成只读 SQLite 数据库、中文短语全文索引与预计算统计。
5. 将数据库和 Next.js standalone 服务一起放入生产镜像。

线上请求不会下载或重建数据。Next.js 直接查询同一容器中的只读 SQLite，
因此搜索不需要外部数据库或跨服务网络请求。

## 本地开发

需要 Node.js 22 或更新版本。

```bash
pnpm install
pnpm run build:data
pnpm run dev
```

打开 <http://localhost:3000>。

`patches/next@16.2.1.patch` 修复 Next.js 客户端页面缓存键丢失重复查询参数的问题，
确保增删多选作者后，结果与 URL 一致。pnpm 安装时自动应用，升级 Next.js 时需验证上游是否已修复。

首次 `build:data` 会下载约 45 MB 压缩数据并生成本地数据库。下载文件会复用；
只要数据清单和索引版本未变化，后续执行会直接使用现有数据库。

### 预览本地数据仓库

先在相邻的 `shici-data` 仓库生成发布资源：

```bash
cd ../shici-data
python3 scripts/build_release.py --version local

cd ../shici
SHICI_DATA_MANIFEST=../shici-data/dist/manifest.json \
SHICI_DATA_ASSET_DIRECTORY=../shici-data/dist \
  pnpm run build:data
```

环境变量只影响本地构建，不会修改生产固定的 `data_release.json`。

## Render 部署

仓库根目录的 `render.yaml` 与 `Dockerfile` 定义一个免费 Web Service：

- Docker 构建阶段获取并验证固定的数据发布版本
- `/api/health` 只在数据库可以读取时返回 `200`
- 服务监听 Render 提供的 `PORT`（镜像默认使用 `10000`）
- 免费实例休眠后无需重新索引，因为数据库已经包含在镜像中

在 Render 创建 Blueprint 并连接此仓库即可。生产域名配置为
`NEXT_PUBLIC_SITE_URL`，以生成正确的 canonical、Open Graph、robots 与 sitemap
地址。

## 数据更新

数据与产品代码保持独立：

1. 在 `shici-data` 中修订并发布新版本。
2. 更新本仓库的 `data_release.json`。
3. 运行完整验证。
4. 部署新镜像。

旧版本的 GitHub Release 保持不可变，因此任何生产镜像都可以复现。
网站顶栏显示当前数据版本，并链接到对应的 GitHub Release。
